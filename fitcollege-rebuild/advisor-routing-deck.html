For Kook · HubSpot

Fields and automation

Form fields (internal names)

  • firstname lastname email mobilephone standard
  • zip: normalised 4-digit postcode standard
  • course_interest confirm exists
  • assigned_advisor: advisor name new property
  • lead_form_type: advisor / infopack new property
  • lead_context: e.g. checker-eligible new property
  • hubspot_owner_id: sets Contact owner confirm form allows

Automation

  1. Contact owner via hidden hubspot_owner_id. Backup: a workflow on assigned_advisor (10 branches, not 2,664).
  2. SMS speed-to-lead names the advisor. If the lead has already booked, send a booking confirmation, not "we'll call you shortly".
  3. Non-website leads (Meta lead ads, imports) are routed from hubspot-postcode-owner.csv, so routing matches everywhere.
  4. Fallback: create a round-robin team meeting link.

Edge cases & upkeep

No dead ends, no code edits

SituationBehaviour
Postcode not in sheet / overseas / typoTeam calendar + 1300 number; tagged for gap reporting
NT typed as "800"Padded to 0800 → Sam Russell
Border postcodes (11 rows)Owner as per sheet, no action
HubSpot submit failsCalendar still shows; booking creates the contact
JavaScript blockedForm posts natively to HubSpot (today's behaviour)
Submits twiceDe-duped on email; latest postcode wins

When territories change

  1. Update POSTCODE MASTER (same columns: POSTCODE, STATE, OWNER).
  2. New advisor? Add a row to data/advisors.csv.
  3. Run python3 tools/build_advisor_routing.py "POSTCODE MASTER.xlsx". It prints counts and stops on any clash.
  4. Deploy the regenerated js/advisor-data.js.
