Postcode is in POSTCODE MASTER

Postcode not in the sheet (e.g. 2055 North Sydney)

The HubSpot form · what the website needs

FIT College builds the form; the website plugs into it

The form and everything after submission is handled in-house. The website only needs these.

FIT College sends

  • Portal ID and form ID
  • Form editor: new or legacy
  • Region: ap1
  • Any extra hidden fields the website must fill
  • After submit: inline message, not a redirect, so screen 2 can replace it

Website reads (after submit)

  • firstname · lastname · email: prefill the calendar
  • course_interest: options match course-routing.csv exactly
  • where_do_you_live: Australia / Outside Australia
  • zip or country

Website writes (hidden)

  • lead_source_page: page they came from
  • lead_context: e.g. checker-eligible
  • UTMs, gclid, fbclid from the URL
  • Legacy embeds only: assigned_advisor, lead_routing
  • Course preselected from the source page

Edge cases & upkeep

No dead ends, no code edits

SituationBehaviour
Postcode not in sheetTeam promise + call option; lead_routing = unmatched for gap reports
OverseasCountry instead of postcode; international phone via country code
Advisor calendar empty (leave, full)"No times showing? Call 1300 887 017" under the calendar
Came straight to contact pageCourse defaults to "Not sure yet"; source page = contact
Spam botsHubSpot reCAPTCHA
JavaScript blockedPhone number shown instead

When territories or courses change

  1. Update POSTCODE MASTER and/or course-routing.csv.
  2. New advisor? Add a row to advisors.csv.
  3. Run python3 tools/build_advisor_routing.py "POSTCODE MASTER.xlsx". It stops on any clash.
  4. Deploy the regenerated js/advisor-data.js.
